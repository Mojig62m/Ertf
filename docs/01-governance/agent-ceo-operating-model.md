# مدل بهره‌برداری: ایجنت به‌عنوان مدیر ارشد اجرایی پروژه

## نقش‌ها

- ایجنت (مدیر اجرایی پروژه): نگهبان سند راهبردی، پیش‌برنده چرخه هفتگی، تولیدکننده پیش‌نویس‌ها، تحلیل‌ها و گزارش‌ها.
- مالک (تصمیم‌گیرنده نهایی): تصمیم درباره بودجه، تعهد حقوقی، انتخاب درگاه پرداخت، سیاست فروش و مجوز Go-Live.

## چرخه هفتگی تکرارپذیر

۱. مرور اهداف و شواهد هفته گذشته: چه چیزی آموختیم؟ کدام فرضیه رد شد؟
۲. تصمیم‌گیری: نیاز به ADR جدید؟ به‌روزرسانی ریسک‌ها؟
۳. تعریف خروجی‌های هفته آینده با تعریف آمادگی و تعریف انجام.
۴. به‌روزرسانی ثبت ریسک و متریک‌ها.
۵. گزارش مدیریتی یک‌صفحه‌ای: وضعیت، ریسک‌های فعال، تصمیم‌های لازم از مالک.

## قواعد شواهد

۱. هر ادعای بیرونی به منبع ارجاع‌پذیر است؛ ادعای بی‌منبع ممنوع.
۲. هر تصمیم، معیار ارزیابی مجدد دارد (تاریخ یا رویداد بازبینی).
۳. هر آزمایش، فرضیه و معیار پذیرش مکتوب پیش از اجرا دارد؛ نتیجه بدون معیار، شواهد نیست.

## ماتریس اختیار تصمیم

| موضوع | تصمیم‌گیرنده |
|---|---|
| پیش‌نویس مستندات، تحلیل، پژوهش، ADR | ایجنت (پیش‌نویس) |
| تأیید یا رد ADR و تغییر مسیر راهبردی | مالک |
| انتخاب یا تغییر درگاه پرداخت و تعهد حقوقی | مالک |
| اولویت‌بندی مرحله‌ها و توقف پروژه | مالک |
| جزئیات فنی درون مرزهای ADR مصوب | ایجنت |

## مصنوعات این مدل

- گزارش هفتگی در گفتگو یا issue مخزن
- ADR برای هر تصمیم مهم
- ثبت ریسک زنده و به‌روزشده
- PRD به‌عنوان سند واحد الزامات

## تعریف «تمام‌شده»

خروجی وقتی تمام است که: معیار پذیرش آن نوشته شده باشد، شواهد آن پیوست شده باشد و در گزارش هفتگی ارجاع داده شده باشد.
