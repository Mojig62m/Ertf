# خط پایه معماری

## مسیر درخواست

مرورگر → رابط فروشگاه (Astro + Svelte/Preact) → API (Hono) → منطق دامنه → PostgreSQL

## ماژول‌ها و مرزها

| ماژول | مسئولیت | قواعد مرز |
|---|---|---|
| کاتالوگ و جست‌وجو | محصولات، دسته‌ها، کشف | فقط خواندن داده مرجع؛ بدون نوشتن وضعیت تراکنش |
| حساب کاربری | احراز هویت، نمایه | مالک هویت؛ سایر ماژول‌ها با شناسه ارجاع می‌دهند |
| سبد خرید | انخاب‌ها و محاسبه مبلغ | محاسبه نهایی قیمت فقط در سرور |
| سفارش | وضعیت و چرخه عمر | فقط از درون این ماژول وضعیت سفارش تغییر می‌کند |
| موجودی | کنترل هم‌زمانی رزرو | عملیات اتمی؛ بدون ردو بدل |
| مدیریت | عملیات مدیریتی | دسترسی نقش‌محور؛ جدا از مسیر مشتری |
| پایش | رویداد، لاگ، خطا | بدون داده شخصی در لاگ |

## ناورداهای سیستمی (غیرقابل نقض)

۱. PostgreSQL تنها منبع حقیقت سفارش، موجودی و پرداخت است.
۲. عملیات ایجاد سفارش و کسر موجودی idempotent است؛ کلید idempotency برای هر عملیات حساس الزامی است.
۳. قیمت و موجودی فقط در سمت سرور اعتبارسنجی می‌شود؛ هر مقدار سمت مشتری نمایشی است.
۴. وضعیت سفارش فقط در یک جهت در چرخه عمر مجاز حرکت می‌کند؛ بازگشت وضعیت، رویداد مستقل و ثبت‌شده است.
۵. کش هیچ‌گاه منبع حقیقت نیست؛ داده کش مشتق و قابل بازتولید از PostgreSQL است.
۶. هر سرویس بیرونی (PSP، ارسال، ایمیل) نقطه شکست مشخص و رفتار جایگزین مستند دارد.

## توسعه با دروازه اثبات

موتور جست‌وجوی مستقل، صف پیام، کش توزیع‌شده، جداسازی میکروسرویس و CDN فقط با شواهد سند راهبردی، بخش ۸ اضافه می‌شوند.
